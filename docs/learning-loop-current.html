Session Start
Context Loading
Before any code runs
Read Auto ~/.claude/CLAUDE.md

Global rules loaded into every session. Includes all development flow rules, defensive coding patterns, and knowledge system directives. This is the primary enforcement mechanism.

Read Auto <project>/CLAUDE.md

Project-specific rules loaded automatically. Stack conventions, pre-PR commands, project structure.

Read Auto ~/.claude/projects/*/memory/MEMORY.md

Per-project session memory loaded into context. Contains project summaries, hard lessons, and workflow state.

Session Start
Conflict Detection
git status, lock files, agents

No knowledge files involved. Checks git status, running processes, and lock files. Pure operational safety.

Step 1a
Clarifying Questions
Probe deeper before planning
Read ~/.claude/knowledge/strategic-decisions.md

CLAUDE.md directive: "Read strategic-decisions.md before questioning." Prior product decisions provide context for whether a new idea aligns or diverges.

Step 1b
Write the Plan
Enumerate paths, trace end-to-end
Read ~/.claude/knowledge/INDEX.md

Stack matching guide consulted to determine which topic files to load. Maps project technologies to relevant knowledge files.

Read ~/.claude/knowledge/*.md (stack-matched)

Topic files loaded based on stack match. E.g., a React Native + Supabase project loads react-patterns.md, database-patterns.md, typescript-patterns.md.

Step 1c
Adversarial Plan Review
Separate agent reviews the plan
Read ~/.claude/knowledge/*.md

Reviewing agent checks plan against knowledge files for "knowledge file gaps" — does the plan contradict or ignore patterns?

Gap: Reviewer has no context proof

The plan reviewer checks for gaps but cannot verify the planning agent actually loaded the right files. If the planner skipped INDEX.md, the reviewer won't know.

Step 2
Implement
Write code on feature branch

Patterns from Step 1 are in context. No explicit re-read of knowledge files. Agent applies loaded patterns during implementation.

Gap: Context compression can lose patterns

For large implementations, context may be compressed. Knowledge loaded at planning time can be silently dropped from the working context, causing the agent to fall back to generic behavior.

Step 3
Test Locally
Tests, linter, type-checker, Playwright

No knowledge files read or written. Runs the project's test suite, linter, and type-checker mechanically.

Gap: Test failures don't auto-capture

When tests fail due to a novel pattern (e.g., "Date without Z suffix is timezone-dependent"), the fix is applied but the pattern is not automatically captured to knowledge files. It relies on the review step to catch it later.

Step 4a
Code Simplification
Simplifier agent on changed files

Code simplifier agent runs on changed files vs main. No knowledge files read — works purely from the diff and general coding principles.

Step 4b
Internal Review
Manual line-by-line diff review

Agent reads full git diff main...HEAD. Checks cross-file consistency, interface compliance, caller safety. No explicit knowledge file read.

Gap: Review doesn't reference knowledge

The internal review checklist is hardcoded in CLAUDE.md, not loaded from knowledge files. Patterns discovered in one project's review can't improve another project's review unless manually added to CLAUDE.md.

Step 4c
CodeRabbit Review
External review tool

CodeRabbit runs with -c .coderabbit.yaml CLAUDE.md. The CLAUDE.md is fed as context, so CodeRabbit indirectly receives knowledge-derived rules, but not the topic files themselves.

Step 4d
Adversarial Review
Category-based checklist + capture
Read Enforced ~/.claude/knowledge/adversarial-review.md

Mechanical checklist loaded. Files classified by category (async, routes, DB, UI, LLM, shell, config, test-only), then only matching tiers run. Pre-push hook blocks without the review marker.

Write Enforced ~/.claude/knowledge/*.md

The primary knowledge capture point. Adversarial review step 7: "Are there new cross-project patterns that should be captured?" Agent writes findings to matching topic files. Hook blocks push without the review marker.

Write <project>/docs/features/*/bugs.md, decisions.md

Project docs updated with feature-scoped bugs, decisions, and QA entries found during review.

Step 4e
CI Checks
Build, lint, test

Build, lint, test run. If fixes produce new changes, loop back to 4c. No knowledge interaction.

Step 5
Push & Create PR
gh pr create with review section
Write PR body: Local Review section

PR body includes structured data for the post-mortem: steps skipped, internal review findings, CodeRabbit findings, adversarial review findings, Playwright status, CI status. This is the data that feeds the self-improvement dashboard.

Step 6
Post-Merge
/post-mortem auto-runs
Write Auto ~/.claude/knowledge/process-patterns.md

Post-mortem appends metrics: shift-left rate, review findings vs GitHub comments, iteration count. Regenerates the self-improvement dashboard at ~/.claude/knowledge/metrics/dashboard.html.

Gap: Post-mortem doesn't update CLAUDE.md

Process patterns accumulate in process-patterns.md but never automatically flow back into CLAUDE.md rules. A pattern like "PRs over 600 LOC degrade shift-left rate" was manually added to CLAUDE.md — there's no automation closing this loop.

Session End
Config Auto-Sync
Push ~/.claude/ changes to git
Write Auto ~/.claude/ → git push origin main

All knowledge, memory, and config changes committed and pushed to the claude-config repo. Makes knowledge available to the next session on any machine.

Session End
Proactive Capture
CLAUDE.md directive
Gap: Proactive capture is purely directive

CLAUDE.md says "when you encounter a bug pattern that could recur, add it to knowledge." This has no mechanical enforcement. The agent may or may not do it. The adversarial review is the only enforced capture point, and it only runs for PRs, not for quick-fix sessions or exploration.

08Known Gaps & Severity

No verification of knowledge consumption

CLAUDE.md says "read INDEX.md and topic files" but there's no mechanical check that the agent actually did it. The only enforcement is the directive itself — an LLM instruction, not a gate.

High — systemic

Context compression drops patterns

Knowledge loaded at Step 1b can be silently lost during long implementations. The agent won't know patterns were compressed away — it just stops applying them.

High — silent failure

Test failures don't auto-capture

A novel test failure pattern (timezone bugs, async race conditions) gets fixed but not captured to knowledge. It relies on the adversarial review to catch it 3 steps later.

Medium — delayed capture

Internal review can't reference knowledge

Step 4b's checklist is hardcoded in CLAUDE.md. Patterns from knowledge/*.md don't feed into the internal review. Each project's review is limited to what's in CLAUDE.md.

Medium — coverage gap

Post-mortem doesn't close the loop

Process-patterns.md accumulates metrics but never auto-updates CLAUDE.md rules. The "600 LOC threshold" rule was manually extracted. Most metrics sit unread.

Medium — stale metrics

Proactive capture is unenforceable

CLAUDE.md has a "Proactive Learning Capture" directive for ad-hoc patterns, but no hook or gate checks for it. Works when it works; invisible when it doesn't.

Low — safety net exists (4d)

PR rejection feedback is manual

When a PR is rejected or "wrong approach" feedback is given, that judgment doesn't flow into knowledge automatically. Requires manual /review-fix invocation.

Low — infrequent event
