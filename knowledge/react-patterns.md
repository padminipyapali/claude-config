# React / React Native Patterns

Cross-project learnings for React and React Native development.

## Hooks

- **Destructure ALL fields from hooks — including `loading`.** When a hook returns `{ data, loading, error }`, always destructure and render ALL three. Ignoring `error` creates silent failures. Ignoring `loading` causes layout jumps: if a parent `isLoading` gate is computed as `OR` of multiple hooks' loading states, each hook's `loading` must be included. Missing one means the gate clears while that hook's data is still pending, producing a visible flash or incorrect partial render (e.g., flat timeline flashing before session-grouped timeline renders). Mechanical check: grep for `useApi(` or custom hook calls and verify all returned fields are destructured. <!-- Source: PR review, command-center #23, 2026-02-19 -->
- **Stale-while-revalidate must block concurrent mutations.** When a cache hit serves stale data instantly and fires a background revalidation request, any mutation that appends/modifies state (e.g., `loadMore`, pagination) can race with the revalidation. The revalidation replaces state with first-page data, clobbering appended rows. Fix: set an `enhancing`/`revalidating` flag immediately on cache hit (before the async revalidation fires) and block mutations while it's true. Use both a `useState` setter (for UI) and a `useRef` (for synchronous guards in callbacks). Pattern: `setEnhancing(true); enhancingRef.current = true;` on cache hit, then in `loadMore`: `if (enhancingRef.current) return;`. **Token guard for teardown:** When multiple background refreshes can overlap (e.g., rapid filter switches), use a monotonic token (`const token = ++tokenRef.current`) captured in the refresh closure. In the `.finally()` block, only clear the flag if `token === tokenRef.current` -- prevents a stale refresh from clearing the flag while a newer one is in flight. <!-- Source: CodeRabbit review, second-brain #339, 2026-03-03; strengthened: second-brain #353, 2026-03-04 -->
- **Memoize functions returned from custom hooks.** If a custom hook returns a function that consumers may use in `useEffect` dependency arrays, wrap it in `useCallback`. An inline `reload: () => { ... }` in a hook's return object creates a new reference every render, causing infinite effect loops. This applies to ANY function returned from a hook — `reload`, `refresh`, `reset`, etc. <!-- Source: PR review, second-brain #90, 2026-02-15 -->
- **IntersectionObserver effects must include error state in guards — with a manual retry path.** When using IntersectionObserver for infinite scroll, a failed `loadMore` flips `loading` back to `false`, the observer effect re-runs, the sentinel is still visible, and `loadMore` fires again immediately — creating a tight retry loop. Fix: add `Boolean(error)` to the early-return guard and `error` to the dependency array. **But blocking the observer also removes the retry path** — if the manual "Load more" button was removed, pagination is permanently stuck after one failure. Always add an inline retry button in the error display when `entries.length > 0 && cursor` (i.e., there are loaded entries and more pages exist). Clicking retry calls `loadMore()`, which clears the error at the top (`setError(null)`), allowing the observer to re-engage. Pattern: `if (!el || !cursor || loading || enhancing || Boolean(error)) return;` with deps `[cursor, loading, enhancing, error, loadMore]`. General rule: when replacing a manual trigger (button) with an automatic trigger (observer/scroll), always preserve a manual recovery path for error states. <!-- Source: CodeRabbit review, second-brain #353, 2026-03-04 (strengthened: round 2) -->
- **Include visibility state in DOM-measuring effects.** When a `useEffect` reads DOM measurements (e.g., `el.scrollHeight` for auto-resize textareas), include the visibility toggle (e.g., `showForm`, `isOpen`) in the dependency array — not just the content state. If the element is conditionally rendered and the content hasn't changed between hide/show cycles, the effect won't fire on reopen, leaving stale measurements (e.g., a textarea at 1-line height despite containing multiline text). Mechanical check: grep for `useEffect.*scrollHeight\|useEffect.*offsetHeight\|useEffect.*clientHeight` and verify deps include the boolean that gates the element's rendering. <!-- Source: PR review, second-brain #315, 2026-03-02 -->
- **Unmount guard on async fetches — two patterns.** (1) When async lives inside `useEffect`: use `let active = true` with cleanup `active = false`, check `if (active)` before state setters. (2) When async lives in `useCallback` called from `useEffect`: use `useRef(true)` (`isMountedRef`) with a separate cleanup effect, check `isMountedRef.current` before state setters. Pattern (2) is needed because the callback outlives any single effect invocation — a local `let` flag would be scoped wrong. When a hook already has a staleness guard (e.g., `currentKeyRef`), combine both checks: `if (currentKeyRef.current !== key || !isMountedRef.current) return;`. **Strict-mode caveat:** `useRef(true)` + cleanup `ref.current = false` fails under React strict-mode because the cleanup runs between the two mount invocations, leaving the ref `false` on the second mount. Correct pattern: `useRef(false)` + `useEffect(() => { ref.current = true; return () => { ref.current = false; }; }, [])`. <!-- Source: PR review, second-brain #75, 2026-02-14; strengthened: second-brain #140, 2026-02-16; strict-mode: second-brain #288, 2026-02-28 -->

- **Memoize derived config objects from context/settings.** When extracting a config object from context (e.g., `payPeriodConfigFromSettings(data.settings)`) and passing it to a pure function, wrap both in `useMemo` with primitive deps (`data.settings.fieldA`, `data.settings.fieldB`). Un-memoized inline calls create new object references every render, defeating downstream memoization and triggering unnecessary re-renders of children that depend on the result. <!-- Source: PR review, nanny-app #28, 2026-02-19 -->
- **Hook `load()` must set error state on failure AND clear it on success.** When a custom hook has an async `load()` function with a try/catch, both paths must manage error state: (1) **catch:** call `setError(err)` — silently swallowing errors hides real outages from the UI. (2) **success path:** call `setError(null)` — without clearing, a transient error persists visually even after a successful retry. The combination of swallowing errors and never clearing creates the worst UX: stale error messages that don't reflect reality, or completely invisible failures. Mechanical check: for each `try/catch` in a hook's async function, verify `setError(null)` is in the try body (after the await succeeds) and `setError(err)` is in the catch body. <!-- Source: PR review, second-brain #248, 2026-02-25 -->
- **`new Date()` inside `useMemo` needs a date-based dependency.** If a `useMemo` calls `new Date()` to compute date-dependent values (e.g., current pay period bounds), the memo will go stale if the app stays open past midnight — the dependency array doesn't change, so the memo never recomputes. Fix: add a day-granularity key (e.g., `getTodayISO()` or `new Date().toDateString()`) to the dependency array. Mechanical check: grep for `useMemo.*new Date\(\)` and verify the deps include a date token. <!-- Source: PR review, nanny-app #28, 2026-02-19 -->

## State Management

- **Sync `useState` from async props with `useEffect`.** `useState(prop?.value ?? default)` only uses the initial value on mount. If the prop arrives asynchronously (e.g., fetched after the component renders), the state never updates. Fix: add a `useEffect` that calls `setState(prop.value)` when the prop changes. Apply symmetrically — if summary syncs on `!== undefined`, notes should too, or one field goes stale while the other updates. <!-- Source: PR review, command-center session-annotations, 2026-02-20 -->
- **Inline editing "clear" guard: compare against previous value, not empty string.** When building an inline editor with a "no-op" guard that cancels if the value hasn't changed, compare against the previous value (`trimmed === (prevValue ?? "")`), NOT against empty string (`trimmed === ""`). Guarding on empty blocks the "clear" action — the user can never delete existing text. Also: the Save button's `disabled` prop must use the same comparison. Mechanical check: grep for `trim() === ""` in save handlers and verify it's not blocking a valid clear. <!-- Source: PR review (CodeRabbit), second-brain #349, 2026-03-04 -->
- **New editing modes must join ALL existing edit-mode guards.** When adding a second inline editing mode (e.g., `editingCaption` alongside `editing`), add it to EVERY place the first mode is checked: card click suppression, `clickable` class, `role="button"`, `tabIndex`, `onKeyDown`. Missing one lets card navigation fire during the new edit mode, losing draft text. Mechanical check: grep for the existing edit flag (e.g., `editing`) and verify the new flag appears in every guard. <!-- Source: PR review (CodeRabbit), second-brain #349, 2026-03-04 -->
- **Optimistic UI revert must capture previous state AND guard against stale reverts.** Never invert (`!e.starred`) to revert — if multiple toggles race, the inverse is wrong. Capture the previous value BEFORE the optimistic update and restore it on failure. **Additionally:** guard the revert with a staleness check — only revert if the item's current value still matches the optimistic value you set (`e.status === newStatus`). Without this guard, a slow-failing request reverts over a later successful update when the user rapidly changes the same item. Pattern: `prev.map(e => e.id === id && e.status === optimisticValue ? { ...e, status: prevValue } : e)`. **Multi-state cascade:** when the optimistic action calls a helper function that clears multiple states (e.g., `closeSession()` clears activeSession, turns, AND ideaSuggestion), snapshot ALL those states before the action and restore each one in the catch block. Use state setter functions for rollback (`setX(current => current ?? previous)`) to guard against the user navigating elsewhere during the in-flight request — unconditional `setX(previous)` clobbers newer state. <!-- Source: PR review, second-brain #269, 2026-02-26 (strengthened: #277, 2026-02-27) -->
- **Zustand over Context for performance-sensitive shared state.** React Context re-renders ALL consumers on any state change, regardless of which slice changed. For state consumed by many components (e.g., account balances, user preferences), use Zustand with selectors for granular subscriptions — only the components reading the changed slice re-render. Context is fine for low-frequency state (theme, auth), but becomes a bottleneck when updates are frequent or consumers are numerous. <!-- Source: folio QA, 2026-02-23 -->
- **Reset local state on context change via `key` prop or `useEffect`.** When a child component uses `useState` and the parent re-renders with different data (e.g., navigating to a different entry), local state persists because React preserves state for same-position components. Preferred: use a `key` prop based on the changing context ID to force a remount and reset all local state — catches ALL state, including state added later. Example: `<RelatedEntriesSection key={entryId} ... />`. Exception: when remounting is expensive (e.g., a complex panel with scroll position, input text, or multiple sub-hooks), use a targeted `useEffect(() => { setError(null); setRetrying(false); }, [contextId])` instead. This preserves the component tree but requires manually listing each state var to reset — easy to forget when adding new state later. Mechanical check: grep for `useState` in components whose props include a context ID (entryId, sessionId, etc.) and verify each transient state (errors, loading flags, form modes) resets on context change. <!-- Source: PR review, second-brain #226, 2026-02-24; strengthened: second-brain #288, 2026-02-28 -->
- **Close popup state on mode transitions.** When a component has both a popup (date picker, dropdown, tooltip) and an edit mode, reset the popup's open state in the edit-start handler (`setShowPopup(false)`). Without this, entering edit mode while the popup is open leaves it visible but stale — the popup references pre-edit state and can obscure edit controls. Mechanical check: grep for `setEditing(true)` or `handleEditStart` in components that also have `showPopup`/`showDatePicker` state, and verify the popup is closed. <!-- Source: PR review, second-brain #186, 2026-02-19 -->
- **Reversal actions must clear ALL side-effect state.** When any action (cancel, undo, revert) reverses a prior operation, it must clear ALL state that the original operation produced — not just the primary change. This includes: error state, confirmation prompts, cascade prompts, loading indicators, and secondary UI triggered as side effects. Example: Cancel button must clear error state (`setError(null)`). Undo callback must clear cascade prompts (`setPendingCascade(null)`) that were triggered by the original edit. Mechanical check: for every cancel/undo handler, enumerate all `setState` calls in the original action's success path, and verify the reversal clears each one. <!-- Source: PR review, second-brain #215, 2026-02-24; strengthened: sleep-tracker #12, 2026-03-03 -->
- **Draft state for sequential async saves — don't re-read from props between saves.** When a component saves individual fields to an async store (Firestore, API) and composes sibling field values from props for each save, there's a latency window where props haven't updated yet from the previous save. A rapid second edit reads stale sibling values and overwrites the first edit. Fix: maintain local `draftTimes`/`draftValues` state as the source of truth. Initialize from props, update optimistically on each successful save, sync back from props via `useEffect` when the subscription pushes new values. Undo must also revert draft state. **Error-path rollback:** when optimistically updating draft before the async save, capture `const prev = draftTimes` before mutating, build `const next = { ...prev, field: newValue }`, and in the catch block call `setDraftTimes(prev)`. Without this, a failed save leaves the UI showing unsaved values and subsequent edits compose with incorrect state. Pattern: `const prev = draft; const next = {...prev, field}; setDraft(next); try { await save(next); } catch { setDraft(prev); setError(...); }`. Mechanical check: in components with multi-field inline editing backed by async saves, verify the save handler reads sibling values from local state (not props) AND rolls back draft on failure. <!-- Source: PR review, sleep-tracker #13, 2026-03-03; strengthened: sleep-tracker #17, 2026-03-03 -->
- **Dedup when resolving optimistic entries — real data may already be present.** When replacing an optimistic entry with server-confirmed data (`resolveOptimisticEntry(tempId, realEntry)`), the real entry might already exist in the list from a background refresh or concurrent fetch. Filter out BOTH the optimistic ID and the real entry's ID before inserting: `prev.filter(e => e.id !== optimisticId && e.id !== realEntry.id)`. Without this, the same entry appears twice — once from the background refresh and once from the resolve. Also handle the case where the optimistic entry was already removed (background refresh replaced it): fall back to prepending the real entry. <!-- Source: PR review, second-brain #324, 2026-03-02 -->
- **CSS `pointer-events: none` is insufficient for disabling interactive elements.** When marking elements as non-interactive (optimistic/loading states), CSS `pointer-events: none` only blocks mouse events — keyboard navigation (`Tab`, `Enter`, `Space`) still works. Must also add explicit guards in event handlers (`if (isOptimistic) return`) and conditionally render or disable interactive controls. Pattern: use BOTH `pointer-events: none` (visual feedback) AND handler-level guards (actual enforcement). Mechanical check: grep for `pointer-events: none` in changed CSS and verify matching components have handler-level guards. <!-- Source: PR review, second-brain #324, 2026-03-02 -->
- **Re-sort after optimistic state changes that affect display order.** If a list is sorted by a derived property (e.g., IN_PROGRESS items first), the optimistic `prev.map(e => ...)` that changes that property must also re-sort. Without it, the item stays in its old position until the next reload. Pattern: `.map(update).sort(comparator)`. Applies to both the happy path and pagination (`loadMore`). <!-- Source: PR review, second-brain #159, 2026-02-19 -->
- **Track individual items when detecting state transitions in collections.** Don't track only collection length (e.g., `prevItems.length > 0` vs `items.length === 0`) to detect transitions like "all items are now complete." Length-only detection misses individual completions when other items remain — you can't tell if an item transitioned or was added/removed. Fix: track item IDs in a Set: `const wasAllDone = Set<id>(...prevItems).size === 0` and `const isNowAllDone = Set<id>(...items).size === 0`. Applies to: active-to-completed transitions, empty-to-populated state, filtering-out-all-matches patterns. <!-- Source: CodeRabbit review, second-brain #213, 2026-02-23 -->
- **Local "submitted" flag to prevent child-parent prop update flicker.** When a child component calls `await onSubmit()` and then resets its mode (e.g., `setFeedbackMode(null)`), the parent's prop update (e.g., `task.feedback`) hasn't arrived yet — the child re-renders in its default state with stale props, causing buttons to briefly reappear. Fix: add a local `submitted` state, set it `true` after the async call succeeds, and include it in the guard (e.g., `const hasFeedback = task.feedback !== null || submitted`). Reset the flag via `useEffect(() => { setSubmitted(false); ... }, [entity.id])` — prefer `useEffect` over render-phase `prevId` comparison pattern (`if (id !== prevId) { setPrevId(id); setState(...) }`), which violates React's "render must be pure" rule and triggers ESLint's `set-state-in-render`. The useEffect approach also lets you reset ALL local state cleanly in one place. <!-- Source: PR review, second-brain #215, 2026-02-24 (strengthened: round 2) -->
- **Ref-based flags need no-op guards.** When using a ref as a flag to skip an effect on internal actions (e.g., `isInternalNavRef.current = true` before calling `onNavigate`), guard against no-op calls where the action doesn't change the dependency. If `onNavigate(targetId)` is called with `targetId === currentId`, the effect's dependency doesn't change, so the effect never fires to clear the flag — leaving it stuck `true` and breaking future external navigations. Fix: bail out early if the action is a no-op (`if (targetId === currentId) return;`) before setting the flag. <!-- Source: PR review, second-brain #215, 2026-02-24 -->
- **Zustand + React: atomic state transitions.** Never create intermediate states that match auto-start effect triggers. If an effect watches `sessionId=null && isCreating=false` to auto-start, then `restartSession` must set BOTH fields in a single `set()` call. Separate calls create observable intermediate states.
- **When bypassing a re-entrancy guard, inline the logic.** If `restartSession` needs to call `startSession()` after atomically setting its guard flag, inline the body — don't call through the guard that will reject it.

## React Native Specific

- **FlatList `extraData` for external state.** FlatList memoizes `renderItem` aggressively. Any state used inside `renderItem` that isn't part of the `data` array MUST be passed via `extraData`. Common gotcha: async-loaded data (e.g., word bank via SSE) doesn't trigger re-render of existing items.
- **Unmount guards on ALL XHR handlers.** Every `onprogress`, `onload`, `onerror` handler must check `isMountedRef.current` as its first line — not just retry handlers, but initial request handlers too. Abort-on-unmount is insufficient because the abort races with handler invocation.
- **Abort in-flight XHR on session/context change.** When a session ID changes, abort active XHR before resetting state to prevent stale data leaking.

## UI Patterns

- **Grep for `role="button"` — replace with `<button>`.** Any `<span>`, `<div>`, or `<a>` with `role="button"` must become `<button type="button">`. Mechanical check: `grep -rn 'role=.*button' --include='*.tsx'` on changed files, inspect every match. Native `<button>` gives keyboard handling (Enter/Space, tab focus) for free and satisfies Biome `noStaticElementInteractions`. **Exception:** elements containing interactive children (`<a>` links) must stay as `<span role="button" tabIndex={0}>` with `onKeyDown`, because `<a>` inside `<button>` violates HTML content model. **For table rows:** do NOT use `<tr role="button">` — it conflicts with table semantics and confuses assistive technology about whether the element is a data row or interactive control. Instead, place a native `<button type="button">` inside one cell (typically the name/title cell) with `aria-label` and `onClick`. The `<tr>` stays as a pure data row; keyboard access comes from the native button for free. **When using `role="button"` (non-table cases), always add `aria-label`** — unlike native `<button>` which derives its name from text content, elements with `role="button"` often contain complex child markup that screen readers won't announce cleanly. <!-- Strengthened: PR review, second-brain #143, 2026-02-17; command-center #62, 2026-02-28; command-center #77, 2026-03-02 -->
- **`aria-label` is invalid on non-interactive, non-focusable generic elements.** Don't add `aria-label` to `<span>`, `<div>`, or `<p>` unless the element has an interactive role (`button`, `link`, `tab`, etc.) or is focusable (`tabIndex`). Screen readers may ignore `aria-label` on generic elements, and Biome's `noAriaUnsupportedOnRole` flags it. If the text is already visible as the element's text content, the label is redundant. Mechanical check: grep changed `.tsx` files for `aria-label` and verify each target element is interactive or focusable. <!-- Source: PR review, command-center #62, 2026-02-28 -->
- **`:focus-visible` must mirror `:hover` on every interactive element.** When adding `:hover` styling (background change, border highlight, etc.) to buttons, cards, or controls, always add a matching `:focus-visible` rule. Without it, keyboard users see no visual feedback when tabbing through controls. Pattern: `.btn:hover { background: ... }` requires `.btn:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px; }`. Mechanical check: grep changed CSS for `:hover` and verify each selector also has a `:focus-visible` rule. <!-- Source: PR review (CodeRabbit), second-brain #359, 2026-03-04 -->
- **Module-level caches must be invalidated on auth transitions.** When a hook uses a module-level cache (e.g., `let todayCardCache: T | null = null`) for fast initial render, the cache persists across login/logout in the same runtime — a second user sees the first user's data. Fix: always revalidate on mount (the cache serves as optimistic initial state, not a gate). Pattern: `useEffect(() => { void load(); }, [load]);` instead of `useEffect(() => { if (!cache) load(); }, [load]);`. This ensures fresh data after auth transitions while still rendering cached data instantly. <!-- Source: PR review (CodeRabbit), second-brain #359, 2026-03-04 -->
- **`aria-pressed` on toggle buttons.** Any button that toggles between on/off states (filter chips, star buttons, mute toggles) must have `aria-pressed={isActive}`. Without it, screen readers announce the button but not its current state. Easy to miss because the visual styling (active class) communicates state to sighted users but is invisible to assistive technology. <!-- Source: PR review, second-brain #125, 2026-02-16 -->
- **Dynamic `aria-label` on multi-state buttons.** When a button changes its *purpose* across states (not just on/off toggle, but e.g., "Delete" → "Confirm delete" → "Deleting..."), use a dynamic `aria-label` that describes the current action. `aria-pressed` is wrong here because the button isn't toggling — it's progressing through a confirmation flow. Screen readers announce static labels even as the visual glyph changes (× → ✓), leaving users unaware the button is armed. <!-- Source: PR review, sleep-tracker #39, 2026-03-04 -->
- **Disable edit-trigger buttons during async saves.** When a button opens an inline editor (time picker, modal, etc.) and the editor's save is async, disable the trigger button while `saving` is true. Without this, rapid sequential edits build payloads from stale prop snapshots — the second edit overwrites the first because props haven't updated with the Firestore write yet. Pattern: `disabled={saving}` + `onClick={() => !saving && openEditor()}` (defense-in-depth). <!-- Source: PR review, sleep-tracker #39, 2026-03-04 -->
- **SVG `<title>` for accessibility.** Every inline `<svg>` must have a `<title>` child for screen readers.
- **Visual progress bars need full ARIA semantics.** Any `<div>` rendered as a progress indicator (width-based fill, gradient bar, etc.) must have `role="progressbar"` with `aria-valuenow`, `aria-valuemin`, `aria-valuemax`, and `aria-label` or `aria-valuetext`. Without these, screen readers see a meaningless empty div. Mechanical check: grep changed `.tsx` files for width-percentage styles or `progressPercent` and verify the container has `role="progressbar"`. <!-- Source: CodeRabbit review, sleep-tracker #14, 2026-03-03 -->
- **`aria-hidden` on decorative indicators + `aria-label` for state.** Visual-only elements (notification dots, status icons) need `aria-hidden="true"` to avoid screen reader noise. Communicate the state via `aria-label` on the parent interactive element instead (e.g., `aria-label="Inbox, unread items"`). <!-- Source: PR review, second-brain #75, 2026-02-14 -->
- **Decorative SVG icons: `aria-hidden="true"` + `focusable="false"` + remove `<title>`.** When an SVG is inside a labeled button/link (`<button aria-label="...">`), mark it decorative AND remove the `<title>` element. **Why:** Screen readers announce both the `aria-label` AND the `<title>` content (especially NVDA + Chrome), resulting in duplicate/confusing announcements (e.g., "Delete button, delete" or "Favorite button, favorite star"). Fix: set `aria-hidden="true"` and `focusable="false"` on the `<svg>`, remove the `<title>`, and let the parent button's `aria-label` communicate the action. Only add `<title>` to standalone meaningful SVGs that don't have a labeled parent. Mechanical check: grep changed `.tsx` files for `<svg>` with `<title>` and verify the parent element has `aria-label` — if yes, remove the `<title>` and add the a11y attributes. <!-- Source: CodeRabbit review, second-brain #213, 2026-02-23 -->
- **UTC for date bucketing in multi-client dashboards.** When grouping items by day ("Today", "Yesterday", etc.) in a web dashboard, use UTC dates for comparison — not local timezone. Local timezone creates inconsistent grouping across clients. Compare using `getUTCFullYear()`/`getUTCMonth()`/`getUTCDate()` and pass `timeZone: "UTC"` to `toLocaleDateString`. Also hoist reference dates (today, yesterday) outside loops. <!-- Source: PR review, command-center #12, 2026-02-15 -->
- **ARIA live regions for loading/status indicators.** Skeleton loaders, "Refining results..." spinners, and other visual-only loading states are invisible to screen readers. Wrap loading containers in `role="status"` (or use `<output>`, which has implicit `role="status"`) with `aria-live="polite"` and `aria-busy="true"`. Add a visually hidden `<span className="sr-only">` with descriptive text (e.g., "Searching..."). For multi-phase loading (initial → refining → done), announce each phase. Mechanical check: grep changed `.tsx` files for `loading` state renders, skeleton components, and status text — verify each has a live region or `role="status"`. **Important:** Biome's `useSemanticElements` rule suggests `<output>` for `role="status"`, but `<output>` is semantically for computed form results — NOT loading/status indicators. Use `<div role="status">` with a `biome-ignore lint/a11y/useSemanticElements` comment. **Content model constraint:** If using `<output>`, it permits only phrasing content (`<span>`, text) -- NOT block elements (`<div>`, `<section>`, or components that render divs like Masonry grids). Keep the sr-only `<span>` inside `<output>` and render block-level skeleton grids as siblings with `aria-hidden="true"`. <!-- Source: CodeRabbit review, second-brain #339, 2026-03-03 (strengthened: #353, 2026-03-04) -->
- **Collapsible sections: `aria-hidden` + conditional `tabIndex` on hidden children.** When interactive elements (`role="button"`, `tabIndex={0}`) live inside a collapsible container (`maxHeight: expanded ? "800px" : "0px"`), they remain keyboard-reachable when collapsed — creating invisible focus targets. Fix: (1) add `aria-hidden={!expanded}` on the collapsible container, (2) set `tabIndex={expanded ? 0 : -1}` on all interactive children. This prevents Tab from landing on hidden elements. Mechanical check: grep for `tabIndex={0}` inside elements whose parent has a `maxHeight` or `display` transition — verify tabIndex is conditional on visibility. <!-- Source: PR review, sleep-tracker #8, 2026-03-02 -->
- **Non-interactive elements inside clickable containers need `stopPropagation`.** When converting interactive elements (`<button>`) to non-interactive display elements (`<span>`) inside a clickable container (e.g., a card `<div>` with `onClick`), the old `stopPropagation` from the button's click handler is lost. Clicks on bare spans bubble to the parent and trigger unintended navigation. Fix: add `onClick={(e) => e.stopPropagation()}` to the span even though it's non-interactive — this absorbs clicks without making the element focusable or semantically interactive. Mechanical check: when removing `onClick` handlers from elements inside clickable containers, verify no sibling/parent click handler is exposed. <!-- Source: PR review, second-brain #226, 2026-02-24 -->
- **Never add `onClick` to a non-interactive container `<div>` — move logic to child handlers.** Adding `onClick={(e) => e.stopPropagation()}` to a wrapper `<div>` triggers Biome a11y errors (`noStaticElementInteractions`, `useKeyWithClickEvents`) because `<div>` is not an interactive element. Instead of adding `role`, `tabIndex`, and `onKeyDown` to the div, move the `e.stopPropagation()` into each child interactive element's own `onClick` handler (e.g., the button's `onClick`). This is both more accessible and more precise — it stops propagation only from actual user interactions, not from any click anywhere inside the container. Mechanical check: grep changed `.tsx` files for `<div onClick` and verify the div has `role` + keyboard handling, or refactor the handler into child elements. <!-- Source: PR review, second-brain #248, 2026-02-25 -->
- **stopPropagation() for stacked dismissible layers.** When a modal sits over a panel, or a drawer over an overlay, keyboard events (Escape) and click-outside handlers fire on ALL layers simultaneously. Call `e.stopPropagation()` in the topmost layer's handler to prevent cascading dismissals. **For inline edit modes inside dismissible panels:** use `onKeyDownCapture` on the edit container, not `onKeyDown` on the textarea alone — if focus moves to Save/Cancel buttons, textarea-only handlers won't fire and Escape closes the panel instead of cancelling the edit. <!-- Strengthened: PR review, second-brain #143, 2026-02-17 -->
- **`white-space: pre-wrap` for newline-formatted text.** Any container rendering user-facing text with `\n` line breaks needs `white-space: pre-wrap`. HTML collapses newlines by default. Easy to miss because text appears correct in channels that preserve newlines natively (Telegram, terminal). <!-- Source: BUG-W003, second-brain -->
- **Grid headers need `grid-column: 1 / -1`.** When a non-card element (header, label) lives inside a CSS grid container, it must explicitly span all columns or it consumes a grid cell and creates a visual gap. <!-- Source: BUG-W004, second-brain -->
- **Use CSS `columns` over JS masonry libraries for height-balanced card layouts.** Libraries like `react-masonry-css` use round-robin index-based distribution (card 1→col 1, card 2→col 2, etc.) which ignores card heights — resulting in some columns being empty while others overflow. CSS `column-count` + `column-gap` does true height-balanced content distribution natively, with `break-inside: avoid` on children to prevent card splitting. Responsive breakpoints via `@media` queries on `column-count`. Only reach for JS masonry when you need specific card ordering (e.g., newest-first left-to-right) that CSS columns don't support (CSS columns fill top-to-bottom, left-to-right). <!-- Source: bug fix, second-brain #383, 2026-03-06 -->
- **CSS grid `repeat(N)` must match actual data column count.** When `grid-template-columns` hardcodes a column count (e.g., `repeat(12, 1fr)`), it must match the number of columns the data actually renders. A mismatch causes silent layout misalignment — cells still render but in wrong grid positions. Verify by checking the data source (array length, loop count) against the CSS value. Especially dangerous when the data count changes during development but the CSS isn't updated. <!-- Source: PR review, summer-camps #3, 2026-02-28 -->
- **Fallback text after content stripping.** When displaying user content with URLs/markup stripped (e.g., button labels, preview text), the result can be empty. Always provide a fallback: `content.replace(PATTERN, "").trim() || "Untitled"`. Applies to any pipeline that strips before displaying. <!-- Source: PR review, second-brain #159, 2026-02-19 -->
- **Hover-only affordances need touch and keyboard fallbacks.** CSS `opacity: 0` on hover (e.g., delete buttons on list items) hides controls from touch devices and keyboard users. Always add: (1) `:focus-within` on the parent to reveal on keyboard focus, (2) `@media (hover: none) and (pointer: coarse)` to always show on touch devices, (3) `:focus-visible` on the button itself for direct focus styling. Mechanical check: grep changed CSS for `:hover` that sets `opacity` and verify sibling rules exist for focus-within and touch. <!-- Source: PR review, second-brain #277, 2026-02-27 -->
- **Truncated text needs `title` attribute.** When using `text-overflow: ellipsis`, always pair with a `title` attribute or tooltip so users can access the full value on hover. Especially important for URLs. <!-- Source: BUG-020, second-brain -->
- **Fallback rendering for unknown enum values from API.** When rendering values via a lookup object (e.g., `Record<StatusEnum, string>`), always add a `?? rawValue` fallback. The backend may emit new enum values before the frontend is updated, and a missing lookup key returns `undefined`. Without a fallback, the UI renders blank instead of displaying the raw value. Pattern: `statusLabels[entry.status] ?? entry.status` or for color lookups `colors[type] ?? 'gray'`. Mechanical check: find all computed lookups in changed render methods and verify each has a `??` fallback. <!-- Source: CodeRabbit review, second-brain #213, 2026-02-23 -->
- **Modal stacking: sibling overlay+dialog need independent `z-index`.** When overlay and dialog are siblings (not parent-child), both need `position` and explicit `z-index`. Flex centering only works if the dialog is a child of the overlay. <!-- Source: BUG-019, second-brain -->
- **Conditional className stripping breaks layout.** Never use `className={condition ? "" : "layout-class"}` — the empty string removes flex/overflow/scroll styles from the wrapper, breaking layout for the conditional branch. Instead, render the wrapper conditionally: `{condition ? renderDirect() : <div className="layout-class">{renderWrapped()}</div>}`. Subtle because the component renders without errors but scroll/overflow silently breaks. <!-- Source: PR review, command-center #77, 2026-03-02 -->
- **Pluralize user-facing counts.** Always use `{count} item{count === 1 ? "" : "s"}` (or a helper) for counts displayed to users. Easy to miss when the count is rarely 1 during development. Check all `{variable} noun` patterns in changed JSX. <!-- Source: PR review, command-center #77, 2026-03-02 -->
- **Abbreviated labels need a11y labels.** When shortening visible text for compactness (e.g., "Passing" → "PASS"), always pair with `aria-label` (full text for screen readers) and `title` (hover tooltip for mouse users). The visual abbreviation communicates to sighted users but is ambiguous for assistive technology. <!-- Source: PR review, command-center #77, 2026-03-02 -->
- **Scroll preservation on DOM height changes.** When injected content changes height (skeleton → real text, lazy-loaded section), use `useLayoutEffect` to capture `scrollTop` before the change and restore it via `requestAnimationFrame` after DOM settles. Prevents jarring scroll jumps. <!-- Source: second-brain DECISIONS -->
- **Mutual exclusion between overlapping panels.** When two panels can occupy the same screen area (thread detail + sidebar), keep them mutually exclusive: opening one closes the other. Prevents visual clutter and simplifies state management. <!-- Source: second-brain DECISIONS -->
- **Never filter paginated results client-side.** If the server returns N items per page and the client filters some out, the visible count is unpredictable — a page of all-filtered items shows "No entries found" despite data existing. Push filtering to the server SQL query so pagination operates on the final result set. <!-- Source: BUG-021, second-brain #100, 2026-02-15 -->
- **Keyboard shortcut input suppression must cover all editable elements.** When implementing global keyboard shortcuts via `document.addEventListener("keydown", ...)`, the handler must suppress shortcuts when focus is inside ANY editable element: `INPUT`, `TEXTAREA`, `SELECT`, and `contentEditable` containers. Missing even one (commonly `SELECT`) causes shortcuts to fire during user input. Also guard against modifier keys (`metaKey`, `ctrlKey`, `altKey`) to avoid conflicts with browser/OS shortcuts. Pattern: `const tag = (e.target as HTMLElement)?.tagName; if (tag === "INPUT" || tag === "TEXTAREA" || tag === "SELECT" || (e.target as HTMLElement)?.isContentEditable) return; if (e.metaKey || e.ctrlKey || e.altKey) return;`. Mechanical check: grep for `addEventListener.*keydown` in changed files and verify the suppression guard covers all four element types. <!-- Source: critic review, second-brain #344, 2026-03-04 -->
- **iOS Safari auto-zoom: minimum 16px font-size on form inputs.** Any `<input>`, `<textarea>`, or `<select>` on a mobile-facing web page must have a computed font-size of at least 16px (1rem at default root size) to prevent iOS Safari's auto-zoom behavior. When fixing one input, grep for pattern siblings — all focusable form elements in the stylesheet need the same minimum. <!-- Source: BUG-W008, second-brain, 2026-02-16 -->
- **Undefined CSS custom properties fail silently.** Using `var(--border)` when the variable isn't defined in the theme's `:root` or scope means CSS silently falls back to the property's initial value (e.g., `none` for `border`, `transparent` for `background`). This is invisible during development if the default happens to look acceptable. Always verify CSS custom property names against the `:root` or theme definition. Mechanical check: grep changed CSS for `var(--` and confirm each property name exists in the theme file. <!-- Source: PR review, second-brain #164, 2026-02-19 -->
- **Tokenize hardcoded colors into CSS custom properties — don't leave hex/rgba in component styles.** When adding or updating colors in component inline styles or CSS, always define them as CSS custom properties in `:root` (or the theme file) and reference via `var(--token-name)`. Hardcoded values like `#FFE5D9` or `rgba(125, 211, 160, 0.3)` scattered across components make theming impossible, create inconsistency when the palette evolves, and are hard to audit. Use `var(--token, #fallback)` for resilience. Mechanical check: grep changed `.tsx` and `.css` files for raw `#[0-9a-fA-F]` and `rgba(` in style attributes — each should reference a CSS variable instead. <!-- Source: CodeRabbit review, sleep-tracker #25, 2026-03-03 -->
- **Use instance-unique IDs for `htmlFor`/`id`/`name` in reusable components.** Static `id="my-textarea"` and `name="myRadio"` break label association and radio grouping when multiple instances of a component render on the same page. Fix: suffix with a unique prop (e.g., `` `refine-textarea-${task.id}` ``). Even if only one instance renders today, a future layout change can add a second. React 18+ also offers `useId()` for this purpose. Mechanical check: grep changed `.tsx` files for static `id=` and `name=` on form elements and verify they're unique per instance. <!-- Source: PR review, second-brain #215, 2026-02-24 -->
- **`placeholder` is not an accessible label — always add `aria-label` on form inputs.** Screen readers may not announce `placeholder` as the field's name. Every `<input>` and `<textarea>` needs either a `<label htmlFor>` or `aria-label`. Similarly, icon-only buttons (e.g., "+" submit) need `aria-label` describing the action. Mechanical check: grep for `placeholder=` in changed `.tsx` files and verify each element also has `aria-label` or an associated `<label>`. <!-- Source: PR review, command-center #33, 2026-02-20 -->
- **`aria-controls` must accompany `aria-expanded` on collapsible toggles.** When a button has `aria-expanded`, screen readers need `aria-controls` pointing to the controlled element's `id` to provide navigation context. Without it, `aria-expanded` tells the user something is open/closed but not what or where. Simple 2-line fix: add `id` to the controlled element and `aria-controls={id}` to the button. <!-- Source: PR review, second-brain #164, 2026-02-19 -->
- **All infinite animations must have `@media (prefers-reduced-motion: reduce)` overrides.** CSS animations with `animation: ... infinite` must include a media query that disables or removes the animation for users with reduced motion preference. This is a WCAG 2.1 Level AA requirement. Pattern sibling check: when adding an infinite animation, grep the stylesheet for existing infinite animations and verify they ALL have the override — common to add one animation and miss others in the same file. **CRITICAL:** In the reduced-motion block, use `animation: none !important` (not plain `animation: none`). When animation rules are scattered throughout the file, later rules in the file win due to CSS cascade (same specificity, later source order). The `!important` flag guarantees the override can't be shadowed. Example: if `@keyframes pulse` and `animation: pulse` appear AFTER the `@media (prefers-reduced-motion)` block, they win — use `!important` to ensure reduced-motion always wins. <!-- Source: CodeRabbit review, second-brain #213, 2026-02-23 (strengthened with cascade/specificity detail) -->

- **Plan notification/indicator dismissal paths upfront.** When adding a notification, progress indicator, or dismissible UI element to a feature, always plan how it gets cleared: explicit user action (close button), timeout, state transition, or server update. Don't add it as a TODO for later — incomplete dismissal paths lead to stale indicators and confusing UX. If you must defer, add a clear TODO and track it. Mechanical check: for every new notification/indicator in the PR, ask "How does this go away?" <!-- Source: CodeRabbit review, second-brain #213, 2026-02-23 -->

## General Web UI

- **Don't rely on Unicode characters for icons — use SVG.** Unicode rendering varies across platforms and fonts. SVG icons have consistent sizing and styling across all browsers and devices.
- **Don't impose arbitrary UI truncation — make content expandable.** When content length varies (user input, AI output, lists), don't hard-truncate to a fixed size. Use expandable containers ("Show more") so users can access full content.
- **Use placeholder hints instead of default values for user-configurable settings.** Pre-filling a setting with a default value makes it unclear whether the user intentionally chose that value or never configured it. Use `placeholder="e.g., 9:00 AM"` instead of `value="9:00 AM"`.

## Data Flow & Derived State

- **Aggregate counts must use unfiltered data when the count represents the total.** When a UI shows filtered items (e.g., hiding routine events in a calendar) but also displays a summary count (e.g., "3 events today" in a footer), the count must derive from the unfiltered source data, not the filtered display list. Otherwise, filtering out items makes the count show 0 even when events exist. Mechanical check: for every derived count in a component, trace it back to its data source and verify it's the correct scope (filtered vs. unfiltered). <!-- Source: PR review, second-brain #187, 2026-02-20 -->

## Component Design

- **Extract shared conditional logic on first duplication.** When adding a new mode/variant (e.g., `isNightNurse`) that changes calculation logic in multiple components, extract the branching into a shared utility function immediately — don't copy the `if/else` into each component. Waiting creates divergence risk and always gets caught in review. Pattern: `calculateTotalPay(hours, ..., settings, isVariant)` returning a unified result shape. <!-- Source: CodeRabbit review, nanny-app #26, 2026-02-19 -->

## Testing React Components

- **Case-insensitive dedup for display lists.** When building UI lists from AI-generated data, use `Set<string>` with `.toLowerCase()`.
- **Use scoped index keys for static lists with potential duplicate content.** When rendering a static list (pros/cons, tags, bullet points) where items are strings that may repeat, don't use the string value as `key` — duplicates cause React reconciliation bugs. Use index-based keys scoped to the parent: `` key={`${parentId}-pro-${index}`} ``. Plain `key={index}` works for single-instance lists, but scoped keys prevent collisions when multiple instances render on the same page. <!-- Source: PR review, summer-camps #3, 2026-02-28 -->
- **Deduplicate array data at every consumption point — rendering AND logic.** When a component receives `urls: string[]` (or any array), add `const unique = Array.from(new Set(items))` before every `.map()` and `.filter()`. Two distinct failure modes: (1) **Rendering:** duplicate keys cause React reconciliation bugs and ambiguous toggle state. (2) **Business logic:** filtering the raw array (e.g., `urls.filter(u => selected.has(u))`) produces duplicate entries in composed output even when the UI shows one checkbox per unique item. Both must be deduped independently — fixing rendering doesn't fix the filter path. <!-- Source: PR review, second-brain #294, 2026-02-28 -->
